# API

Через API можно проверить работу системы, найти книгу, посмотреть ее экземпляры, добавить читателя или сотрудника и получить рекомендации.

- [Открыть Swagger UI](swagger.html) — посмотреть все ручки, поля и примеры ответов.
- [Открыть файл OpenAPI](openapi.yaml) — описание API в формате YAML.

Это учебное описание: работающий сервер не нужен. Адрес `https://example.com/api/v1` приведен для примера. Отправка запросов в Swagger отключена.

## Кто может пользоваться API

Проверки `/health` и `/health/ml` доступны без входа. Для остальных ручек нужен токен — строка, по которой система узнает пользователя. Он передается в заголовке:

```http
Authorization: Bearer <token>
```

Как пользователь входит в систему и получает токен, в этой работе не описываем.

| Роль | Что разрешено |
| --- | --- |
| Читатель (`reader`) | Искать доступные по возрасту книги и получать рекомендации |
| Библиотекарь (`librarian`) | Смотреть весь каталог, экземпляры книг и их штрихкоды |
| Администратор (`admin`) | Смотреть весь каталог и экземпляры, добавлять читателей и сотрудников |

## Ручки API

| Метод и путь | Что делает | Успешный ответ | Возможные ошибки |
| --- | --- | --- | --- |
| `GET /health` | Проверяет приложение и каталог | `200` | `503` |
| `GET /health/ml` | Проверяет модель рекомендаций | `200` | `503` |
| `GET /books` | Ищет книги по названию и автору | `200` | `400`, `401`, `403`, `503` |
| `GET /books/{bookId}` | Возвращает книгу и количество доступных экземпляров | `200` | `400`, `401`, `403`, `404`, `503` |
| `GET /books/{bookId}/copies` | Возвращает экземпляры книги со штрихкодами | `200` | `400`, `401`, `403`, `404`, `503` |
| `POST /readers` | Добавляет читателя | `201` | `400`, `401`, `403`, `409`, `500` |
| `POST /staff` | Добавляет администратора или библиотекаря | `201` | `400`, `401`, `403`, `500` |
| `POST /recommendations` | Подбирает до пяти книг по интересам | `200` | `400`, `401`, `403`, `503`, `500` |

### 1. Проверить систему — `GET /health`

Без параметров. Возвращает `200`, если приложение и каталог работают, или `503`, если система временно не готова к работе.

### 2. Проверить модель — `GET /health/ml`

Без параметров. Возвращает `200`, если модель готова, или `503`, если она недоступна либо не ответила за 5 секунд. При отказе модели обычный поиск книг продолжает работать.

`408` здесь не нужен: он означает, что сервер не дождался полного запроса от клиента, а не ответа модели. Если само приложение выключено, оно вообще не сможет вернуть HTTP-ответ.

### 3. Найти книги — `GET /books`

Например:

```http
GET /books?title=Мастер&author=Булгаков
```

`title` и `author` необязательны. Можно передать часть названия или имени автора; регистр букв не важен. Если указать оба поля, книга должна подходить под оба. Без этих полей возвращается список книг.

Список выдается частями: `limit` — сколько записей вернуть (по умолчанию 20, максимум 100), `offset` — сколько пропустить (по умолчанию 0). Порядок — по возрастанию `id`.

Ответ содержит `items` — книги, `total` — общее число найденных книг, а также `limit` и `offset`. Если ничего не найдено, возвращается `200` и пустой `items`.

Читатель видит только доступные по возрасту книги. Если дата рождения в его карточке не заполнена или ошибочна, возвращается `400`. Сотрудники видят весь каталог.

### 4. Посмотреть книгу — `GET /books/{bookId}`

Вместо `{bookId}` нужно указать положительный целочисленный ID книги, например `/books/42`.

Ответ содержит название, автора, возрастную маркировку и `availableCopies` — количество экземпляров в наличии. Для сотрудника книга со всеми выданными экземплярами возвращается с `200` и `availableCopies: 0`.

Для читателя книга без доступных экземпляров или с неподходящей возрастной маркировкой скрыта: возвращается `404`, как и для несуществующей книги.

### 5. Посмотреть экземпляры — `GET /books/{bookId}/copies`

Доступно библиотекарю и администратору. У одной книги может быть несколько физических экземпляров, и у каждого свой штрихкод.

Ответ содержит `items`, `total`, `limit`, `offset`. Для каждого экземпляра указаны `id`, `catalogRecordId` (ID книги), `barcode` и `status`: `available` — в фонде, `issued` — выдан. Параметры `limit` и `offset` работают так же, как в поиске книг.

Данные читателя, которому выдана книга, не возвращаются. Если книга существует, но экземпляров нет, ответ — `200` с пустым списком. Если самой книги нет — `404`.

### 6. Добавить читателя — `POST /readers`

Доступно администратору. Обязательны ФИО, дата рождения и штрихкод билета. Интересы можно не передавать — тогда сохраняется пустая строка.

```json
{
  "fullName": "Иван Петров",
  "birthDate": "2005-04-12",
  "ticketBarcode": "READER-000123",
  "interests": "Космос и научная фантастика"
}
```

Дата рождения не может быть в будущем, а штрихкод билета должен быть уникальным. ФИО не может быть пустым или состоять только из пробелов. Штрихкод содержит латинские буквы, цифры или дефис.

При успехе — `201` и данные читателя с новым `id`. Если билет уже зарегистрирован — `409`.

### 7. Добавить сотрудника — `POST /staff`

Доступно администратору. Обязательны ФИО и роль: `admin` — администратор, `librarian` — библиотекарь.

```json
{
  "fullName": "Анна Смирнова",
  "role": "librarian"
}
```

При успехе — `201` и поля `id`, `fullName`, `role`. Сотрудники могут иметь одинаковые ФИО. Эти ручки добавляют сведения о людях; настройку паролей и вход в систему здесь не описываем.

### 8. Получить рекомендации — `POST /recommendations`

Доступно читателю. Нужно передать `interests` — текст интересов от 1 до 2000 символов, не только пробелы.

```json
{
  "interests": "Космос, путешествия и научная фантастика"
}
```

Система сама определяет читателя по токену и берет дату рождения из его карточки. Передавать ID читателя или возраст не нужно.

Сначала выбираются доступные по возрасту экземпляры. Затем модель сравнивает интересы с описаниями книг. В ответе — до пяти разных книг, сначала самые подходящие. У каждой указаны `book` (данные книги), `editionId` (ID экземпляра), `score` (оценка сходства от 0 до 1, без нуля) и `position` (место в списке).

Если оценки равны, первым идет экземпляр с меньшим ID. Одна книга не повторяется, даже если у нее несколько экземпляров. Оценка — не вероятность того, что книга понравится. ФИО и дата рождения модели не передаются.

Поле `reason` объясняет результат:

| Значение | Что произошло |
| --- | --- |
| `matched` | Найдено от 1 до 5 книг |
| `no_candidates` | Нет доступных по возрасту книг; список пуст, модель не вызывается |
| `no_matches` | Нет совпадений по интересам; список пуст, стоит изменить интересы |

Все три случая — успешный ответ `200`. Ошибка модели, неверный ответ или ожидание дольше 5 секунд дают `503`. Тогда предлагается обычный поиск.

Рекомендация не бронирует и не выдает книгу. При выдаче доступность проверяется заново. Историю рекомендаций не сохраняем.

## Ошибки

У всех ошибок одинаковый формат:

```json
{
  "code": "BOOK_NOT_FOUND",
  "message": "Книга не найдена или недоступна читателю"
}
```

HTTP-статус показывает тип ошибки, `code` — конкретную причину для программы, `message` — пояснение для человека.

| HTTP-статус | Код в JSON | Значение |
| --- | --- | --- |
| `400 Bad Request` | `INVALID_REQUEST` | Ошибка в JSON, полях или параметрах запроса |
| `400 Bad Request` | `INVALID_INTERESTS` | Неверно заполнены интересы |
| `400 Bad Request` | `INVALID_BIRTH_DATE` | Дата рождения не указана, ошибочна или находится в будущем |
| `401 Unauthorized` | `UNAUTHORIZED` | Нет действительного токена |
| `403 Forbidden` | `FORBIDDEN` | У пользователя нет прав на эту ручку |
| `404 Not Found` | `BOOK_NOT_FOUND` | Книги нет или она недоступна читателю |
| `409 Conflict` | `TICKET_BARCODE_EXISTS` | Билет с таким штрихкодом уже зарегистрирован |
| `503 Service Unavailable` | `APPLICATION_NOT_READY` | Приложение временно не готово к работе |
| `503 Service Unavailable` | `CATALOG_UNAVAILABLE` | Каталог недоступен |
| `503 Service Unavailable` | `ML_UNAVAILABLE` | Модель недоступна |
| `503 Service Unavailable` | `ML_TIMEOUT` | Модель не ответила за 5 секунд |
| `503 Service Unavailable` | `ML_INVALID_RESPONSE` | Модель вернула неверные ID или оценки |
| `500 Internal Server Error` | `INTERNAL_ERROR` | Неожиданная ошибка сервера |

## Что такое Schema и зачем нужен `$ref`

Schema — описание полей объекта: как они называются, какого типа и какие обязательны. Вместо повторения одного описания в разных ручках на него ссылаются через `$ref`.

Например, схема `Book` используется в поиске, карточке книги и рекомендациях:

```yaml
schema:
  $ref: '#/components/schemas/Book'
```

| Схема | Что описывает |
| --- | --- |
| `Error` | Общий ответ с ошибкой |
| `HealthStatus` | Успешную проверку состояния |
| `Book`, `BookCopy` | Книгу и ее физический экземпляр |
| `BookPage`, `CopyPage` | Список книг или экземпляров с полями для выдачи частями |
| `ReaderCreate`, `Reader` | Данные для добавления читателя и ответ с его ID |
| `StaffCreate` | Данные для добавления сотрудника |
| `StaffMember` | Общие поля сотрудника: ID, ФИО, роль |
| `Administrator`, `Librarian` | Администратора и библиотекаря |
| `RecommendationRequest` | Интересы читателя |
| `Recommendation`, `RecommendationResult` | Одну рекомендацию и весь ответ подбора |

В YAML также встречаются `allOf` — объединить описания, `oneOf` — выбрать один вариант. У сотрудников общие поля взяты из `StaffMember`, а конкретный вариант определяется полем `role`. Для этого используется `discriminator` — указание, по какому полю различать варианты.

## Как проверить в Swagger

Открыть [Swagger UI](swagger.html) и раскрыть `POST /recommendations`. Проверить, что видны:

- метод и путь;
- обязательное поле `interests` и пример запроса;
- успешный ответ `200` и его поля;
- ошибки `400`, `401`, `403`, `503`, `500` и примеры;
- схемы в разделе Schemas.

Затем раскрыть `GET /books/{bookId}` и проверить обязательный параметр `bookId`. Отправлять настоящие запросы не нужно.
