# Система учета и выдачи книг с рекомендациями

## Назначение проекта

АС «УВК» автоматизирует учет библиотечного фонда и читателей, поиск, выдачу и возврат изданий. Система учитывает дату рождения читателя и возрастную маркировку издания: 0+, 6+, 12+, 16+ или 18+.

ML-модуль рекомендаций ранжирует доступные книги по интересам читателя и помогает выбрать подходящее издание.

Возрастная фильтрация — обязательная проверка по правилам, а не предсказание модели. Сначала система исключает недоступные и не подходящие по возрасту издания, затем сравнивает интересы читателя с заранее сохраненными векторами оставшихся книг. Перед оформлением выдачи возраст и доступность проверяются повторно.

## Основные пользователи

- **Читатель** — ищет книги и получает рекомендации по своим интересам.
- **Библиотекарь** — оформляет выдачу и возврат изданий.
- **Администратор** — ведет каталог и создает карточки читателей и сотрудников.

В системе есть читатель (`Reader`), администратор (`Administrator`) и библиотекарь (`Librarian`). У сотрудников общие поля: ID, ФИО и роль. Они описаны в `StaffMember`. Роль `admin` означает администратора, `librarian` — библиотекаря.

## Основные функции

1. Ведение каталога изданий и карточек читателей с датой рождения.
2. Авторизованный поиск доступных изданий с обязательной возрастной фильтрацией для читателя; сотрудникам доступен весь каталог.
3. Подбор и ранжирование книг по интересам читателя.
4. Оформление выдачи и возврата с обновлением статуса экземпляра.

Подбор, выдача и возврат книг описаны в [требованиях](requirements.md). Взаимодействие компонентов и структура системы представлены на [UML-диаграммах](diagrams.md).

## API

В этой работе описываем восемь ручек:

- `GET /health` и `GET /health/ml` — проверить приложение и модель;
- `GET /books` — найти книги;
- `GET /books/{bookId}` — посмотреть книгу и ее наличие;
- `GET /books/{bookId}/copies` — посмотреть экземпляры и штрихкоды;
- `POST /readers` — добавить читателя;
- `POST /staff` — добавить администратора или библиотекаря;
- `POST /recommendations` — получить рекомендации.

Проверки состояния доступны без входа. Для остальных запросов нужен токен пользователя. Вход в систему и настройку паролей здесь не описываем.

Читатель видит доступные по возрасту книги, сотрудники — весь каталог. Штрихкоды экземпляров доступны только сотрудникам. Добавлять читателей и сотрудников может администратор.

Выдача и возврат остаются функциями системы, но ручки для них пока не описываем. Поля запросов, ответы и ошибки приведены в [разделе API](../api/index.md).

## ML-модуль рекомендаций

Для подбора используется многоязычная модель [`intfloat/multilingual-e5-small`](https://huggingface.co/intfloat/multilingual-e5-small). Она превращает каждый текст в отдельный вектор из 384 чисел.

Когда администратор добавляет или изменяет книгу, модель один раз обрабатывает ее название, жанры и аннотацию с префиксом `passage:`. Вектор сохраняется в реляционной базе. При запросе рекомендаций модель отдельно обрабатывает только интересы с префиксом `query:`. Затем система сравнивает новый вектор с уже сохраненными векторами книг.

- **Вход модели:** один текст `passage:` при подготовке книги или один текст `query:` при запросе читателя. Они не передаются модели одной парой.
- **Выход модели:** один вектор из 384 чисел. Система вычисляет косинусное сходство; отрицательное значение заменяется на `0`, поэтому оценка API находится в диапазоне от 0 до 1.
- **Правило порядка:** по убыванию оценки; при равных оценках — по возрастанию идентификатора издания.
- **Размер списка:** не более пяти разных книг. Экземпляры одной каталожной записи объединяются: остается экземпляр с наибольшей оценкой, а при равенстве — с наименьшим идентификатором. Нулевые оценки не включаются; при отсутствии совпадений система предлагает изменить интересы.
- **Отказ модели:** при ошибке или отсутствии ответа в течение 5 секунд система сообщает о недоступности рекомендаций и предлагает обычный поиск с теми же возрастными ограничениями.

Дата рождения и ФИО не передаются модели: возраст проверяет само приложение. Подробнее модель, датасет и риски описаны в разделе [«ML-модель»](../ml/model-card.md).
