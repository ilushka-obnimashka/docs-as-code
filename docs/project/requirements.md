# Требования

## User Stories

### US-01. Подбор книг по интересам

Как **читатель**, я хочу получать рекомендации книг по своим интересам, чтобы быстрее выбирать подходящие издания.

Критерии приемки:

1. Авторизованный читатель с указанной датой рождения вводит непустой текст интересов; система передает модели только доступные экземпляры с возрастной маркировкой не выше возраста читателя в полных годах.
2. При успешном ответе модели система показывает не более пяти разных книг с положительной оценкой релевантности в порядке убывания оценки; при равных оценках первой идет книга с меньшим идентификатором экземпляра. Для каждой книги видны название, автор и возрастная маркировка. Экземпляры с одинаковым идентификатором каталожной записи не повторяются в результатах.
3. Если кандидатов нет, система сообщает об отсутствии доступных по возрасту книг; если нет положительных оценок — предлагает изменить интересы. При ошибке модели или отсутствии ответа в течение 5 секунд система сообщает о недоступности рекомендаций и предлагает обычный поиск с возрастным фильтром.

### US-02. Выдача книги с проверкой ограничений

Как **библиотекарь**, я хочу оформлять выдачу только доступных и подходящих читателю по возрасту книг, чтобы соблюдать возрастные ограничения и корректно учитывать фонд.

Критерии приемки:

1. При выборе читательского билета и экземпляра система заново проверяет дату рождения читателя, возрастную маркировку и текущий статус экземпляра, даже если книга выбрана из рекомендаций.
2. Если экземпляр доступен и возраст в полных годах не меньше маркировки, система создает операцию выдачи, связывает ее с читателем и экземпляром и меняет статус экземпляра на «выдано» в одной атомарной операции.
3. Если экземпляр уже выдан, возраст недостаточен или дата рождения отсутствует либо некорректна, система показывает причину отказа, не создает выдачу и не изменяет статус экземпляра.

### US-03. Возврат книги

Как **библиотекарь**, я хочу регистрировать возврат книги, чтобы экземпляр снова становился доступным для поиска, рекомендаций и выдачи.

Критерии приемки:

1. По штрихкоду экземпляра система находит незакрытую операцию выдачи и показывает связанного с ней читателя.
2. После подтверждения возврата система сохраняет дату возврата, закрывает операцию выдачи и переводит экземпляр в статус «в фонде» в одной атомарной операции; экземпляр снова доступен для подбора при соблюдении возрастных ограничений.
3. Если штрихкод неизвестен или незакрытая выдача отсутствует, система сообщает причину и не меняет данные.

## UC-01. Получение рекомендаций книг

**Связанная история:** US-01.

**Актор:** читатель.

**Цель:** получить список доступных книг, соответствующих возрасту и интересам читателя.

**Предусловия:** читатель авторизован; в его карточке указана корректная дата рождения, не позднее текущей даты; каталог доступен. Для подбора используются экземпляры с заполненной возрастной маркировкой.

### Основной сценарий

1. Читатель открывает раздел рекомендаций, вводит интересы и отправляет запрос.
2. Приложение проверяет, что текст интересов не пустой, и вычисляет возраст читателя в полных годах на текущую дату.
3. Приложение запрашивает в каталоге только экземпляры со статусом «в фонде» и возрастной маркировкой не выше возраста читателя.
4. Каталог возвращает список подходящих кандидатов с названиями, авторами, жанрами и аннотациями.
5. Приложение передает интересы и описания кандидатов ML-модели, не передавая ФИО и дату рождения.
6. Модель вычисляет оценки релевантности и возвращает ранжированный список идентификаторов и оценок.
7. Приложение проверяет принадлежность идентификаторов кандидатам и корректность оценок, исключает нулевые оценки и сортирует результаты по установленному правилу. Из экземпляров с одинаковой каталожной записью оставляет первый в этом порядке и выбирает не более пяти разных книг.
8. Приложение показывает читателю названия, авторов и возрастные маркировки рекомендованных книг.

### Альтернативные сценарии

- **А1 — пустые интересы (шаг 2):** приложение предлагает заполнить интересы, не обращаясь к каталогу и модели.
- **А2 — нет доступных кандидатов (шаг 4):** приложение сообщает, что доступных по возрасту книг нет; модель не вызывается.
- **А3 — ошибка, отсутствие ответа модели в течение 5 секунд или некорректный ответ (шаги 6–7):** приложение сообщает о недоступности рекомендаций и предлагает обычный поиск; возрастной фильтр не отключается. Некорректным считается ответ с посторонним или повторяющимся идентификатором либо нечисловой оценкой или оценкой вне диапазона от 0 до 1.
- **А4 — нет положительных оценок (шаг 7):** приложение сообщает, что совпадений по интересам нет, и предлагает изменить интересы.

**Результат:** читатель получает до пяти подходящих книг либо понятное сообщение о причине отсутствия рекомендаций. Получение рекомендаций не резервирует экземпляры и не создает операций выдачи.

## Доступ и создание карточек

Проверки состояния доступны без входа. Для остальных ручек нужен токен пользователя в заголовке `Authorization: Bearer <token>`. Вход и получение токена в этой работе не описываем. Если действительного токена нет — `401`, если не хватает прав — `403`.

| Метод и путь | Доступ и ограничения |
| --- | --- |
| `GET /health`, `GET /health/ml` | Публичные проверки состояния приложения и ML-модуля. |
| `GET /books`, `GET /books/{bookId}` | Авторизованные `reader`, `librarian`, `admin`. Для читателя обязательна возрастная фильтрация, в том числе при обращении по идентификатору; сотрудники видят весь каталог без возрастного ограничения. |
| `GET /books/{bookId}/copies` | Только `librarian` и `admin`; ответ не содержит персональных данных читателей, которым выданы экземпляры. |
| `POST /readers` | Только `admin`; создает карточку `Reader` с ФИО, корректной датой рождения не позднее текущей даты и штрихкодом читательского билета. |
| `POST /staff` | Только `admin`; создает карточку `StaffMember` с ФИО и ролью `admin` (`Administrator`) или `librarian` (`Librarian`). Другие значения роли отклоняются. |
| `POST /recommendations` | Авторизованный `reader` получает рекомендации для себя по правилам US-01 и UC-01. |

При добавлении человека система проверяет обязательные поля и назначает ему `id`. Пароли эти ручки не создают. Роль сотрудника указывает администратор; читатель не может назначать роли. Правила выдачи и возврата остаются прежними, но ручки для этих операций пока не описываем.

## Общие правила

- Возраст определяется по дате рождения и текущей дате с учетом того, наступил ли день рождения в текущем году. Например, издание 18+ недоступно за день до восемнадцатилетия и доступно в день восемнадцатилетия.
- Допустимые возрастные маркировки: 0+, 6+, 12+, 16+, 18+. Экземпляры без корректной маркировки не участвуют в рекомендациях и не выдаются до исправления карточки.
- Рекомендация не гарантирует последующую доступность экземпляра: другой библиотекарь может выдать его после подбора. Поэтому при выдаче обязательна повторная проверка согласно US-02.
- Экземпляры одной каталожной записи имеют общий `catalogRecordId`. В рекомендации включается только один из них: с наибольшей оценкой, а при равенстве — с наименьшим идентификатором экземпляра.
- Модель не решает, разрешено ли выдавать книгу, и не меняет данные каталога. Ее оценка влияет только на порядок рекомендаций.
