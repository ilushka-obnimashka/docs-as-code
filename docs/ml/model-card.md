# Model Card

## Общая информация

**Название модели:** `intfloat/multilingual-e5-small` (`multilingual-e5-small`).

**Источник:** [Hugging Face](https://huggingface.co/intfloat/multilingual-e5-small).

**Автор / организация:** Liang Wang, Nan Yang, Xiaolong Huang, Linjun Yang, Rangan Majumder и Furu Wei; Microsoft Corporation.

**Задача модели:** поиск текстов по смыслу и оценка их смысловой близости.

**Язык:** многоязычная модель, русский язык поддерживается. Авторы указывают поддержку 100 языков, но качество на языках с небольшим количеством данных может быть ниже.

**Лицензия:** MIT.

Модель имеет 12 слоев, около 0,1 млрд параметров и создает для каждого текста вектор из 384 чисел.

## Использование в проекте

Модель используется для подбора книг по интересам читателя в `POST /recommendations`.

Описание книги векторизуется заранее:

1. Администратор добавляет или изменяет книгу.
2. Система собирает название, жанры и аннотацию в один текст с префиксом `passage:`.
3. Модель независимо создает вектор этой книги.
4. Система сохраняет вектор в реляционной базе данных вместе со ссылкой на карточку книги.

При запросе рекомендаций модель получает только текст интересов с префиксом `query:` и создает еще один вектор. Затем приложение сравнивает вектор запроса с уже сохраненными векторами книг по косинусному сходству. Описания всех книг при каждом запросе заново не обрабатываются.

В PostgreSQL вектор можно хранить в поле `vector(384)` с расширением `pgvector`. Один вектор относится к карточке книги, а не к каждому физическому экземпляру. Если название, жанры или аннотация изменились, вектор книги нужно рассчитать заново.

До сравнения приложение исключает выданные и не подходящие по возрасту экземпляры. ФИО и дата рождения в модель не передаются. Модель влияет только на порядок уже разрешенных книг.

## Входные данные

Модель кодирует каждый текст независимо:

- `passage: <название, жанры и аннотация книги>` — при подготовке вектора книги;
- `query: <интересы читателя>` — при запросе рекомендаций.

Для скорости модель может обработать несколько текстов одним пакетом, но каждый текст все равно получает собственный вектор. `query:` не склеивается с каждым `passage:`.

Например:

```text
passage: Пикник на обочине. Научная фантастика. История о сталкерах и загадочной Зоне.
```

Позже, независимо от книги:

```text
query: космос, путешествия и научная фантастика
```

`query:` и `passage:` — это подсказки о роли текста, которые использовались при обучении E5. Они не означают, что запрос и описание обязательно передаются модели одной парой. Модель отдельно создает оба вектора, а их сходство вычисляет приложение или база данных.

В проекте действуют два разных ограничения:

- интересы читателя — от 1 до 2000 символов; это ограничение находится в OpenAPI-схеме `RecommendationRequest`;
- модель обрабатывает не более 512 токенов вместе с префиксом `query:` или `passage:`; это ограничение задается в токенизаторе E5.

## Выходные данные

Для одного входного текста модель возвращает один вектор из 384 чисел. Сама модель не возвращает ID книги, готовую рекомендацию или вероятность того, что книга понравится.

Приложение нормализует векторы и вычисляет косинусное сходство. Для ответа API отрицательное значение заменяется на `0`, поэтому поле `score` находится в диапазоне от `0` до `1`. Книги с нулевой оценкой не показываются.

## Данные для обучения

Обучение проходило в два этапа:

1. Предварительное обучение примерно на 1 млрд многоязычных пар текстов из Wikipedia, mC4, NLLB, Reddit, Stack Exchange и других источников.
2. Дополнительное обучение примерно на 1,6 млн размеченных пар из MS MARCO, NQ, TriviaQA, SQuAD, MIRACL, Mr. TyDi и других датасетов.

В [Data Sheet](dataset.md) подробнее описан MS MARCO — один из датасетов второго этапа.

## Метрики качества

Авторы приводят следующие результаты:

- MIRACL, среднее по 16 языкам: `nDCG@10 = 60,8`, `Recall@100 = 92,4`;
- Mr. TyDi, среднее по 11 языкам: `MRR@10 = 64,4`;
- Mr. TyDi для русского языка: `MRR@10 = 60,8`;
- английская часть MTEB: `57,9`.

Эти результаты получены на тестовых наборах и не гарантируют такое же качество рекомендаций в нашей библиотеке.

## Ограничения

1. **Ограничение авторов:** модель обрабатывает не более 512 токенов. Конец длинного текста может быть отброшен.
2. **Ограничение авторов:** для задач поиска нужно использовать префиксы `query:` и `passage:`. Без них качество может снизиться.
3. **Ограничение авторов:** качество может быть ниже для языков, которые слабее представлены в обучающих данных.
4. **Потенциальное ограничение для нашего проекта:** модель обучалась на поисковых и общих текстах, а не специально на рекомендациях книг.
5. **Потенциальное ограничение для нашего проекта:** результат зависит от качества аннотации и жанров. Пустое или неверное описание ухудшит рекомендацию.

## Не рекомендуется использовать

Модель не следует использовать:

- для решения, разрешена ли книга читателю по возрасту;
- для автоматической выдачи или бронирования книги;
- как гарантию того, что книга понравится;
- для генерации аннотаций или текстовых ответов: модель возвращает вектор, а не новый текст;
- для важных медицинских, юридических и других решений, не связанных с поиском похожих текстов.
